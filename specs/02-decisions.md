# Locked Decisions

Decisions made during scoping. This file is append-only: new decisions are
added, superseded ones are marked, never silently rewritten.

| Decision | Choice | Rationale |
|---|---|---|
| Language | Python 3.11+ | LangGraph ecosystem; user knows Python |
| Orchestration | LangGraph | Conditional confidence gate is a real branch, not a linear chain — the architectural point of the project |
| Graph store | **networkx** (in-memory, persisted to JSON on disk) | Zero setup cost; Neo4j migration is mechanical later because the schema (see [06-skill-map.md](06-skill-map.md) §Schema) is already Neo4j-shaped (roadmap `03-milestones.md` §Deferred #1) |
| Interface | CLI only | Fastest path to signal; web UI deferred |
| LLM provider | Cloud cheap tier behind a thin `judge()`-style interface (exact model: see [03-milestones.md](03-milestones.md) §Open: model pick) | Judgment quality matters at the judge node — small local models are weakest exactly where this pipeline's core novel piece needs them most; a full run costs pennies. The interface makes later local-model benchmarking a config swap |
| Local models | Not for v1 default; later benchmark experiment (see roadmap `03-milestones.md` §Deferred #6) | If the judge produces garbage scores, we couldn't tell whether the architecture or the model was wrong. Benchmark only after the cloud baseline passes the rubric |
| Human-in-the-loop | ~~Simple stdin prompt loop (print low-confidence items → ask → record override)~~ (superseded by M7 row, 2026-09-27) | True LangGraph `interrupt()` + checkpointer adds resumable-runtime complexity a CLI doesn't need yet (roadmap §Deferred #2) |

| **(Added M7)** LangGraph state does NOT wrap the `SkillGraph` | State is a TypedDict of serializable fields only (paths, flags, stats, decisions); the `SkillGraph` object lives in an in-memory runtime registry keyed by the run's `thread_id`, accessed via the LangGraph `config` | The checkpointer serializes every state channel to disk after every step; a live networkx graph cannot round-trip through that. | **(Added M8)** Validation metric for resume extraction is "resume content covered", not seed recall | Naive set-recall vs. the seed JSON was rejected: the seed aggregates resume versions + PSE docs + older material, so much of it is absent from any one-page resume (verified by text search). The honest check is whether the resume's actual content lands in the graph, reviewed by inspection + targeted string searches | The user provided their real one-page application CV; a metric that penalizes the extractor for source-material differences measures the wrong thing |
| **(Added M8)** Vocabulary bridge: LLM-assisted merge-or-new for unmatched canonical terms | Canonical terms from new inputs that match nothing in the FULL existing vocabulary (seed canonical + implied + JD lexicon + alias values) get one batched LLM verdict (merge into an existing term vs genuinely new); decisions persist to `output/vocab_bridge.json` and apply silently on re-runs. Manual alias entries remain the first line of defense for recurring variants | The alias table was seed-vocabulary-specific; per-variant manual entries don't scale to arbitrary real-world resumes. The bridge replaces the older "LLM-assisted merge only for ambiguous pairs" idea with a concrete trigger. Merge threshold is conservative (when unsure, keep separate) |
| **(Added M10)** OSS sourcing: unauthenticated GitHub Search Issues for the thin slice; stdlib `urllib`, no new dep | Thin slice runs without `GITHUB_TOKEN` (verified live 2026-09-28); `GITHUB_TOKEN` via the `secrets.py` keyring pattern remains the auth path when set (`Authorization: Bearer`). | **(Added M10)** Curated repos as preference re-rank, not hard filter; 2-attempt broaden loop | Attempt 0 strict (label + full keywords + `language:python`); attempt 1 broadened (first token, no language filter) when <3 raw results; results re-ranked to prefer `CURATED_REPOS` | Hard-filtering to curated repos leaves niche gaps (e.g. Data governance) with 0 results, failing the thin-slice done criteria (3–5 issues per top gap). Preference keeps curated signal without starving gaps; the search-and-reason refinement loop is the follow-up |
| **(Added M11)** Local UI: stdlib `http.server` only, no new dep; background thread + status poll; single-run guard; forced `--auto` | `server.py` (`GET /`, `POST /api/run`, `GET /api/status`, `GET /plan.html`, `GET /api/jds`); run = same `cli.py` graph with `auto=True`; 409 while running; options `top_n`/`skip_judge`/`skip_oss`/`no_llm_oss` mirror `cli.py` flags | Same rationale as M10 `urllib` (two GET calls need no framework); judge/synthesis/OSS take minutes so the UI polls instead of blocking; gate/interrupts cannot fire in a browser — `--auto` applies persisted overrides silently |

| **(Added M12)** Judge / gate / OSS caches are shared across all subsets; only ingestion, ranking and synthesis are per-subset | `_shared/` holds `judge_report.json`, `gate_overrides.json`, `oss_issues.json`; each `sNN/` holds `graph.json`, `plan.md`, `plan.html`, `synthesis_report.json` | The judge scores target `T` against `prune_candidates(T, sg.current_skills())` — current skills come from the resume, so the score for `T` is subset-independent. | **(Added M12)** Sampling = seeded random `k=3` subsets **plus** contrastive subsets | Random draws for the typical case; contrastive = 3 near-identical JDs, 3 maximally different, all JDs, singletons (`k=1`) | 16 JDs → 560 triples; random draws overlap heavily, so random-only sweeps spend most runs on near-duplicates. | **(Added M12)** Sweep metrics target the review; they do not replace it | Automatic: top-5 Jaccard stability, per-gap appearance rate, superset consistency, rank churn, grounding check, GFI link status.
