# Locked Decisions

Decisions made during scoping. This file is append-only: new decisions are
added, superseded ones are marked, never silently rewritten.

| Decision | Choice | Rationale |
|---|---|---|
| Language | Python 3.11+ | LangGraph ecosystem; user knows Python |
| Orchestration | LangGraph | Conditional confidence gate is a real branch, not a linear chain — the architectural point of the project |
| Graph store | **networkx** (in-memory, persisted to JSON on disk) | Zero setup cost; Neo4j migration is mechanical later because the schema (see [1-system-overview.md](1-system-overview.md) §Graph Schema) is already Neo4j-shaped (roadmap `5-milestones.md` §Deferred #1) |
| Interface | CLI only | Fastest path to signal; web UI deferred |
| LLM provider | Cloud cheap tier behind a thin `judge()`-style interface (exact model: see [5-milestones.md](5-milestones.md) §Open: model pick) | Judgment quality matters at the judge node — small local models are weakest exactly where this pipeline's core novel piece needs them most; a full run costs pennies. The interface makes later local-model benchmarking a config swap |
| Local models | Not for v1 default; later benchmark experiment (see roadmap `5-milestones.md` §Deferred #6) | If the judge produces garbage scores, we couldn't tell whether the architecture or the model was wrong. Benchmark only after the cloud baseline passes the rubric |
| Human-in-the-loop | Simple stdin prompt loop (print low-confidence items → ask → record override) | True LangGraph `interrupt()` + checkpointer adds resumable-runtime complexity a CLI doesn't need yet (roadmap §Deferred #2) |
| Sourcing | LLM project-idea synthesis only | GitHub Issues API is a fragile external dependency (roadmap §Deferred #3) |
| Seed data | Skills JSON + 13 JDs (user-supplied files, in `data/`) | Doubles as the validation set — the project's own test data |
| Spec structure | Modular specs in flat `specs/`, no nested subdirectories | Each spec evolves independently (roadmap `5-milestones.md` §§Deferred/Open churn; decisions is append-only); ~6 files is the right granularity — finer splitting would hurt navigation |
| **(Added M3)** LLM provider | **DeepSeek V4 Flash 0731** via OpenRouter (`deepseek/deepseek-v4-flash-0731`) | 284B MoE / 13B active — strong reasoning/agent capability at flash-tier pricing (~$0.035/M in, ~$0.106/M out); user has an OpenRouter key. GLM + OpenAI remain configured as calibration fallbacks. Supersedes the earlier "GLM 5.3 Flash" interim pick |
| **(Added M2)** Implied-skill handling | Agentic proposal flow, not a static set: detect implications from CV phrases, propose each with evidence, user approves (y/n/a), approvals persist | User identified the static set as a design gap — a CV never states 100% of skills, and only the user can judge "too generous vs. too strict." Evidence-backed proposals keep the human in control |
| **(Added M2)** External taxonomy | ESCO ICT subset as optional enrichment, graceful fallback to built-in tables | Public skill taxonomies exist (ESCO); use where applicable rather than hand-maintaining everything, but never hard-depend on an external file |
| **(Added post-M6)** Specs evolve as one living target-state document; no per-version spec files | All specs describe the full system (current end goal = v2) with Built/Designed status markers; versions are labels on milestone ranges (v1 = M1–M6, v2 = M7+); milestone numbering stays linear and global; `3-decisions.md` stays append-only | User decision after v1 completion: version-split specs (`specs/v2/`) duplicate content and blur which document is current; the unit of change is the component, not the version. Guardrail: never describe not-yet-built things in language that implies they exist (rules in [.github/copilot-instructions.md](../.github/copilot-instructions.md)) |
| **(Added post-M6)** v2 direction: conversational intake + resume ingestion + evidence-backed skill validation | Users hand over a resume (PDF/DOCX) or skills JSON; one LLM extraction call; triaged ranking-relevant skills validated via concept checklist + applied question with hidden rubric; grades persist (`output/proficiency.json`) on the gate's 1–5 depth scale and pre-fill the gate | Resumes inflate and structured skills JSONs are an artifact of the seed pipeline, not real users; evidence-backed depth beats self-report. Design detail in [1-system-overview.md](1-system-overview.md) §M9 design, milestones M7–M9 in [5-milestones.md](5-milestones.md). Framing: calibration, not a test |
| **(Added M7)** LangGraph state does NOT wrap the `SkillGraph` | State is a TypedDict of serializable fields only (paths, flags, stats, decisions); the `SkillGraph` object lives in an in-memory runtime registry keyed by the run's `thread_id`, accessed via the LangGraph `config` | The checkpointer serializes every state channel to disk after every step; a live networkx graph cannot round-trip through that. Supersedes the old §9 design line "a pydantic state object wraps the SkillGraph" — the graph object remains the single source of truth, just beside the state rather than inside it. Detail in S7 [15-flow-runner.md](15-flow-runner.md) |
| **(Added M7)** Judge-recalibration loop deferred | The "re-judge with stricter rubric as a loop" branch is not built; the gate's depth factor compensates for clustered-high judge scores | M6 validation showed ranking already separates true gaps from bridges; an automatic re-judge loop adds graph complexity for an unobserved problem. Revisit trigger in [5-milestones.md](5-milestones.md) §Open: calibration |
| **(Added M8)** Validation metric for resume extraction is "resume content covered", not seed recall | Naive set-recall vs. the seed JSON was rejected: the seed aggregates resume versions + PSE docs + older material, so much of it is absent from any one-page resume (verified by text search). The honest check is whether the resume's actual content lands in the graph, reviewed by inspection + targeted string searches | The user provided their real one-page application CV; a metric that penalizes the extractor for source-material differences measures the wrong thing |
| **(Added M8)** Vocabulary bridge: LLM-assisted merge-or-new for unmatched canonical terms | Canonical terms from new inputs that match nothing in the FULL existing vocabulary (seed canonical + implied + JD lexicon + alias values) get one batched LLM verdict (merge into an existing term vs genuinely new); decisions persist to `output/vocab_bridge.json` and apply silently on re-runs. Manual alias entries remain the first line of defense for recurring variants | The alias table was seed-vocabulary-specific; per-variant manual entries don't scale to arbitrary real-world resumes. The bridge replaces the older "LLM-assisted merge only for ambiguous pairs" idea with a concrete trigger. Merge threshold is conservative (when unsure, keep separate) |
