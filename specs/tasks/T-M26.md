## Acceptance criteria (checkable, per-change)

1. `tools/start-server.bat --debug` + one extension panel run prints
   request → run → per-node → per-LLM-call lines sharing one `run-id`
   (the run's `thread_id`); the same run without `--debug` produces
   exactly today's output (byte-stable).
2. `--debug` prints no resume/JD text anywhere; `--debug-payloads` prints
   full prompt/response bodies and implies `--debug`.
3. `/api/status` responses expose the `run-id` so panel symptoms map to
   log lines.
4. `debuglog.py` is the only module configuring logging; hooks are no-ops
   when the flags are off; it imports no network module and no `langsmith`.
5. `m26_check.py` asserts 1–4 offline (stubbed LLM, no network) and runs
   from `main()`; `test_m26.py` wraps it for `pytest`.
