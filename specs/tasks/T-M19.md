## Acceptance criteria (checkable, per-change)

1. Panel + plan follow the OS theme automatically (CSS
   `prefers-color-scheme`; no JS required for the system path).
2. A minimal header button cycles Auto → Light → Dark; the choice
   persists in `chrome.storage.local` (`themePref`) and overrides the
   system theme; Auto returns control to the system.
3. The plan follows the panel: override sets `?theme=` on the iframe URL;
   `GET /plan.html?theme=dark|light` injects `data-theme` at serve time;
   any other value is ignored (no attribute injected).
4. `plan.html` stays self-contained and JS-free; its new stylesheet is the
   first one (light + dark palettes via CSS variables). Both surfaces keep
   readable contrast in both themes (inputs, buttons, banner, chips).
5. `m19_check.py` offline PASS (theme CSS + panel wiring + probe-stub
   compatibility + `?theme=` injection incl. rejected values) +
   `test_m19.py`; `ruff check .`, `pytest`, `node --check` clean;
   m10–m18 regressions PASS. Live look at both themes recorded in
   [03-milestones.md](../03-milestones.md) M19.
