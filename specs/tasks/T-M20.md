## Acceptance criteria (checkable, per-change)

1. Any request whose `Origin` header is present and is neither
   `chrome-extension://…` nor the server's own origin
   (`http://127.0.0.1:<port>` / `http://localhost:<port>`) is refused 403
   before any handler logic runs — including `Origin: null`. Requests
   without an `Origin` (navigations, CLI, mN_check harnesses) behave
   exactly as before.
2. `POST /api/run`, `/api/key`, `/api/oauth/state`, `/api/oauth/exchange`
   accept only `Content-Type: application/json`; `POST /api/resume` only
   `application/octet-stream`; anything else 415s.
3. An explicit run-body `skills_path` that is not an existing `.json` under
   the repo root or the OS temp dir is refused 400 before any run starts;
   `_resolve_skills` precedence behavior is unchanged.
4. Panel `serverBase`: `http://` accepted only for `localhost`/`127.0.0.1`;
   other hosts require `https://`; invalid values fall back to the default
   and are never persisted.
5. Spec: §Security posture rewritten with the corrected trust model; the
   M13 decision row's "preflight is the barrier" claim marked superseded;
   M20 decision rows appended; SECURITY-REVIEW.md carries a remediation
   status note.
6. `m20_check.py` offline PASS + `test_m20.py`; `ruff check .`, `pytest`,
   `node --check` clean; m10–m16, m18, m19 regressions PASS.
