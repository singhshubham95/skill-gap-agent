## Acceptance criteria (checkable, per-change)

1. Panel order: AI access (key chip, create/paste key) → mode chips +
   free consent → resume (disclosure + upload) → collect → analyze →
   plan. The free-consent block sits with the mode chips (it governs
   ingestion too).
2. Mode governs ingestion: `rule` → regex extraction, nothing leaves the
   machine; `paid` → LLM extraction via the active provider's endpoint;
   `free` → free-tier models. `POST /api/resume` receives the mode +
   provider and refuses free-mode uploads without `X-Privacy-Ack: 1`
   (gate is not UI-only).
3. Mode-aware cache: rule↔llm artifacts never cross; an LLM request
   never reuses a regex-fallback artifact (quality follows the mode);
   llm artifacts are reused for llm requests (mode + hash match).
4. Disclosure copy stays M21-accurate (all m21_check needles preserved;
   "selected above" wording; extraction-follows-mode note);
   `DISCLOSURE_CONSENT_VERSION` bumped; M16 verbatim disclaimer
   untouched.
5. `m24_check.py` offline PASS (upload contract incl. free-ack refusal,
   cache rules incl. legacy sidecars, panel order + wiring) +
