## Bug (origin: user live pass 2026-10-12)

`cli.py::_profile_gate_overrides` ran `max((confidence, edge_dict), ...)`.
Python compares tuples element-wise, so **two edges with equal confidence
fell through to comparing the dicts** — `TypeError: '>' not supported
between instances of 'dict' and 'dict'` — crashing `gate_needed` right
after judging (the run died between judge and rank). Data-dependent: real
judge scores tie frequently (the user's run had repeated 0.85s); every
offline harness stubs distinct confidences, so it never fired there. The
tuple's dict element was never read afterwards (only the confidence) —
the fix compares plain floats.
