- **Status:** planned
- **Owner:** human
- **Source:** `board/maintenance/2026-11-01.md` §F-22
- **Blocked by:** none

## Why

`m11` is one of the eight kept checks (`specs/03-milestones.md` M28) but
has no pytest wrapper, and the `m10_check.py` / `m12_check.py` main checks
are unwired too. The only CI that runs tests is the release workflow
(`.github/workflows/windows-release.yml`); PRs run path guard only.
Wrapping the full harness `main()` functions directly pollutes shared
module state when pytest runs them alongside the other tests (observed:
five ordering-dependent failures), so this needs isolation, not a wrapper.

## Files to touch (the scope guard permits exactly these)

- `src/skill_gap_agent/`
- `.github/workflows/`
- `maintenance/README.md`

## Acceptance criteria

1. `m10`, `m11`, and `m12` checks run inside the normal `pytest` process
   with no ordering-dependent failures (isolated store/state per check).
2. A PR workflow runs `ruff check .`, `pytest`, and `node --check` on
   ubuntu-latest with no secrets (the M17 17c offline tier).
3. The charter's check list matches what CI actually runs.
