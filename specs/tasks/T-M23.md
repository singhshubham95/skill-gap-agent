## Acceptance criteria (checkable, per-change)

1. `content.js` never programmatically clicks LinkedIn's expand control
   (or anything else) — no `.click()` call remains.
2. On capture of a collapsed description, the script **assists instead**:
   scrolls the expand button into center view, focuses it, and paints a
   persistent Ctrl+F-style yellow highlight + tooltip; capture returns a
   clear error so the panel tells the user to expand and retry.
3. Capture of an already-expanded description behaves exactly as before
   (text + title + URL, same response shape).
4. Capture-scoping guardrails restated in the spec (single page, one
   user click, no batch/scroll harvesting); residual ToS risk recorded
   honestly in the decision row and `SECURITY-REVIEW.md`.
5. `m23_check.py` + `test_m23.py` green (no synthetic click; assist
   wiring present; error message guides); `ruff`, `pytest`, `node --check`
   clean; m10–m16, m18–m22 regressions PASS.
